# SEO audit — pdfandimage.com

Reviewed September 28, 2026. Scope: local Next.js source, all 85 live sitemap pages, all 29 distinct preview images referenced by those pages, Google Search Console, and connected Ubersuggest research. Code fixes below are local and have not been deployed.

## Assessment

The site has a usable SEO foundation: separate tool URLs, server-rendered content, canonical URLs, a working sitemap, and descriptive headings. The main problems are broken blog preview images, blocked rendering assets, inaccurate marketing claims, and weak organic visibility. More metadata or automatically generated articles alone will not resolve the visibility problem. No implementation can guarantee rankings or indexing.

### SEO-01 — Allow rendering assets

Evidence: live `/robots.txt` disallowed `/_next/` for `*`, Googlebot, and Bingbot. Search Console's blocked example was a `.woff2` file in that directory.

Change: removed those three `/_next/` exclusions from `src/app/robots.ts`; retained API restrictions. This lets crawlers fetch rendering resources. It does not guarantee that previously excluded articles will be indexed. [Google's JavaScript SEO guidance](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics) explains the role of accessible rendering resources.

### SEO-02 — Repair blog preview images

Evidence: all 28 blog `opengraph-image` URLs referenced by live metadata returned 500. The older URL named in Search Console also still returned 500. Local execution reproduced `Expected <div> to have explicit "display: flex" or "display: none" if it has more than one child node.`

Change: added the required flex display to the category/domain line in `src/app/blog/[slug]/opengraph-image.tsx`. The HTML build alone did not detect this runtime error. After rebuilding, all 28 blog images and the homepage image returned HTTP 200 with nonempty image bodies.

### SEO-03 — Remove duplicate branding

Evidence: 28 blog posts and six supporting pages combined a manually branded title with the layout's `%s | PDF and Image +` template. For example, the About page repeated the brand twice.

Change: blog titles now use the layout template once; About and Contact use absolute titles; other supporting pages provide unbranded titles. The homepage explicitly uses an absolute title. Canonical URLs and article slugs are unchanged.

### SEO-04 — Use honest revision dates

Evidence: homepage, static pages, and tool sitemap entries used `new Date()`; the shared tool WebPage schema used a fixed publication date and the build date as its modification date.

Change: omitted unknown dates rather than guessing. The 28 article sitemap entries retain their stored `dateModified` values. Those editorial dates still require the publisher to maintain them accurately. [Google uses lastmod when it is consistently accurate](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

### SEO-05 — Correct structured-data assumptions

Change: removed the homepage's invalid `SiteLinksSearchBox` object and the global search action pointing to a query-string search that the homepage does not implement. Removed an unverified founding date and the universal one-minute completion estimate. Escaped `<` when serializing shared tool JSON-LD. FAQ and HowTo objects remain descriptions of visible content.

Do not treat FAQ markup as a trigger for People Also Ask. Google retired HowTo rich results, restricts FAQ rich results, and retired the sitelinks search box. Old claims in `SEO_FIXES.md` and code comments are not evidence of ranking benefits. [FAQ/HowTo changes](https://developers.google.com/search/blog/2023/08/howto-faq-changes), [search-box retirement](https://developers.google.com/search/blog/2024/10/sitelinks-search-box).

### SEO-06 — Align claims with implementation

Confirmed inconsistencies:

- `FileDropzone.tsx` defaults to a 50 MiB limit, while some metadata and FAQs say no file-size limits.
- Ten client tools call processing APIs, including PDF/Office conversions, PDF protection/unlocking, and background removal. Universal “files never leave your browser” claims are incorrect.
- Background removal forwards files to Remove.bg. The privacy page's exceptions do not fully describe this provider or all observed services.
- The upscaler uses Canvas resampling, while the registry and page title advertise AI. `imageSmoothingQuality = 'high'` does not establish a specific bicubic algorithm or AI restoration.
- PDF compression re-saves the document with object streams. It does not implement a target-size optimizer, image downsampling, or guaranteed large reductions.

Removed universal local-processing/unlimited-size statements from shared software schema and corrected root descriptions. Remaining visible homepage, navigation, footer, tool FAQ, About, privacy, blog and reference-file copy should be reviewed together. Verify actual server retention behavior before promising deletion or memory-only processing. This audit is not a legal review or a live conversion-functionality test. [Google's structured-data policy requires representative, nonmisleading content](https://developers.google.com/search/docs/appearance/structured-data/sd-policies).

### SEO-07 — Complete social metadata

The HTTP crawl found 56 pages without `og:image`: 50 tools and six supporting pages. Defining an `openGraph` object in a child page replaces the corresponding inherited metadata object; root images are not automatically retained in the observed HTML. Tool pages also omit `og:url`.

Recommended next change: a shared metadata helper that explicitly includes image, site name, page URL and Twitter defaults, then lets each page supply its own title and description. The existing `/og-image.png` is reachable. This primarily improves shared previews; it is not a direct ranking guarantee. Blog preview endpoints are repaired separately above.

Candidates include always-loaded analytics/navigation code and processing libraries imported before users select a file. Lazy-load heavy processing code on demand, retain reserved ad dimensions, and test a representative PDF page and image page as well as the homepage. Preserve server-rendered instructions and links.

### Practical content sequence

1. Improve the watermark tool and its existing guide with tested steps, supported formats, a genuine before/after example, and clear size/processing information. Target adding a text watermark to JPG/PNG, not removing one.
2. Improve the HEIC tool and existing guide with verified iPhone file-selection instructions, orientation behavior, output quality and realistic conversion limits. Keep tool intent and tutorial intent distinct.
3. Rewrite the four crawled/unindexed articles around actual tested outputs, limitations, original examples and screenshots. Replace generalized claims; avoid artificial word-count targets.
4. Add direct contextual links from each tool to its matching guide. `ToolLayout.tsx` currently links only to the general `/blog` listing. Keep related-tool links and add useful links between genuinely related guides.
5. Review the scheduled blog-generation workflow before expanding publication. Improve the existing 28 articles first; do not publish near-duplicate keyword permutations or unverified capability claims.
